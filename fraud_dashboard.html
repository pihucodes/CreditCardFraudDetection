The problem: extreme class imbalance

Only 492 of 284,807 transactions are fraud. A model that always says “legitimate” would score 99.83% accuracy and catch nothing, so accuracy alone can’t judge this project.

Legitimate 284,315  |  Fraud 492. Handled with stratified split and class_weight instead of resampling.

Logistic Regression catches more fraud (91.8%) but raises a huge number of false alarms: only 6% of its flags are real fraud. Random Forest is the better balance, which is why it was saved as the final model.

Threshold explorer

The model outputs a fraud probability. Moving the cut-off trades false alarms against missed fraud. Drag the slider.

Default 0.5 gives the best F1 (0.829). Lowering to 0.1 catches 89.8% of fraud but precision drops to 26%. The Streamlit app in the notebook uses 0.5.

What was built

1. Load and checkcreditcard.csv, no missing values
2. Split80/20, stratified, random_state=42
3. TrainRandom Forest (100 trees, depth 12, balanced_subsample) plus Logistic Regression baseline with scaling
4. Evaluateprecision, recall, F1, PR curve, ROC, threshold sweep
5. Deploysaved with joblib, Streamlit app takes a CSV and flags fraud
